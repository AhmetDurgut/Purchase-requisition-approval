# Purchase Requisition Approval

A managed, draft-enabled RAP business object for requesting and approving
purchase requisitions, built on SAP BTP ABAP Environment (ABAP Cloud) /
S/4HANA and exposed through a Fiori Elements Object Page built entirely from
CDS annotations.

## Features

- Draft support — save a partially filled-out request and resume later
- Automatic requisition numbering via a number range on submit
- Automatic item numbering (10, 20, 30, ...) as items are added
- Automatic item amount calculation (Quantity × Price), with the header
  total kept in sync automatically
- Currency inherited consistently from the header to every item
- Requester auto-filled from the logged-in user
- Explicit status flow (Draft → Pending → Approved / Rejected / Info
  Requested) with actions only enabled at the right point in the flow
- Mandatory rejection reason, captured on the request itself
- Color-coded status indicator on the Object Page (grey/yellow/green/red)

## Project structure

| Folder | Contents |
|---|---|
| `database` | `ZPR_HEADER_AD.ddls`, `ZPR_ITEM_AD.ddls` — persistence tables |
| `data-model` | `ZI_PR_HEADER_AD.ddls`, `ZI_PR_ITEM_AD.ddls`, `ZA_PR_REJECT_AD.ddls` — interface views and the reject action's parameter structure |
| `dictionary` | `ZPR_NR_AD.md`, `ZPR_NR_LEN_AD.md` — the number range object (PR numbering) and its supporting domain; documented as specs, not source, since ABAP Cloud maintains both through an ADT form editor, not a text DDL source |
| `behavior` | `ZI_PR_HEADER_AD.bdef`, `ZBP_I_PR_HEADER_AD.clas.abap` — the managed RAP behavior definition and its implementation (Local Handler Class pattern) |
| `projection` | `ZC_PR_HEADER_AD.ddls`, `ZC_PR_ITEM_AD.ddls`, `ZC_PR_HEADER_AD.bdef`, `ZC_PR_ITEM_AD.bdef` — the consumption layer |
| `metadata` | `ZC_PR_HEADER_MDE_AD.ddlx`, `ZC_PR_ITEM_MDE_AD.ddlx` — Fiori Elements UI annotations |
| `service` | `ZUI_PR_HEADER_AD.srvd` — the OData service definition (see [src/service/README.md](src/service/README.md) for why there's no service binding file) |

The folders are listed in build order — each layer is activated on top of
the one before it (`dictionary` before `behavior`, since the behavior
implementation class calls the number range object).

## Setup / Activation

1. Activate in dependency order: `database` → `data-model` → `dictionary` →
   `behavior` → `projection` → `metadata` → `service`.
2. When activating `ZI_PR_HEADER_AD.bdef`, if ADT flags the draft tables
   (`zpr_header_ad_d`, `zpr_item_ad_d`) as missing, use the Quick Fix offered
   directly on the `draft table` lines to generate them — they are not
   hand-written source files in this repo, they're generated by ADT on
   activation.
3. This project hit several non-obvious, environment-specific activation
   problems while being built (a RAP/EML type-generation bug that blocks
   `TYPE TABLE FOR UPDATE`, `CURR`/`QUAN` fields needing a non-released
   check table, circular root/child CDS activation order, and more) — all
   documented with root cause and workaround in
   [docs/type-table-for-update-workaround.md](docs/type-table-for-update-workaround.md).
   Worth reading before activating on a new system, since the workarounds
   are already baked into the source in this repo but the *why* isn't
   obvious from the code alone.
4. Full step-by-step instructions, including creating the service binding
   and previewing the Fiori Elements app, are in
   [docs/cds-odata-setup-guide.md](docs/cds-odata-setup-guide.md).

# Purchase Requisition Approval

SAP BTP ABAP Environment (ABAP Cloud) / S/4HANA üzerine kurulu, satın alma
talebi oluşturma ve onaylama için managed, draft destekli bir RAP business
object. Tamamen CDS annotation'larından oluşan bir Fiori Elements Object
Page üzerinden sunuluyor.

## Özellikler

- Draft desteği — yarım doldurulmuş bir talebi kaydedip daha sonra kaldığın
  yerden devam edebilme
- Submit sırasında bir number range üzerinden otomatik talep numaralandırma
- Item'lar eklendikçe otomatik kalem numaralandırma (10, 20, 30, ...)
- Otomatik kalem tutarı hesaplama (Miktar × Fiyat), header toplamı da
  kendiliğinden güncel kalıyor
- Para biriminin header'dan her item'a tutarlı biçimde miras alınması
- Talep eden alanının, oturum açan kullanıcıdan otomatik doldurulması
- Açık bir durum akışı (Draft → Pending → Approved / Rejected / Info
  Requested), action'ların sadece akışın doğru noktasında aktif olması
- Zorunlu ret gerekçesi, doğrudan talebin üzerinde tutuluyor
- Object Page'de renk kodlu durum göstergesi (gri/sarı/yeşil/kırmızı)

## Proje yapısı

| Klasör | İçerik |
|---|---|
| `database` | `ZPR_HEADER_AD.ddls`, `ZPR_ITEM_AD.ddls` — persistence tabloları |
| `data-model` | `ZI_PR_HEADER_AD.ddls`, `ZI_PR_ITEM_AD.ddls`, `ZA_PR_REJECT_AD.ddls` — interface view'ları ve reject action'ının parametre yapısı |
| `dictionary` | `ZPR_NR_AD.md`, `ZPR_NR_LEN_AD.md` — PR numaralandırması için number range object ve destekleyici domain; ABAP Cloud ikisini de metin tabanlı DDL kaynağı yerine bir ADT form editörüyle yönettiği için kod değil, spesifikasyon olarak dokümante edildi |
| `behavior` | `ZI_PR_HEADER_AD.bdef`, `ZBP_I_PR_HEADER_AD.clas.abap` — managed RAP behavior definition ve implementasyonu (Local Handler Class deseni) |
| `projection` | `ZC_PR_HEADER_AD.ddls`, `ZC_PR_ITEM_AD.ddls`, `ZC_PR_HEADER_AD.bdef`, `ZC_PR_ITEM_AD.bdef` — tüketim katmanı |
| `metadata` | `ZC_PR_HEADER_MDE_AD.ddlx`, `ZC_PR_ITEM_MDE_AD.ddlx` — Fiori Elements UI annotation'ları |
| `service` | `ZUI_PR_HEADER_AD.srvd` — OData servis tanımı (service binding dosyasının neden bulunmadığı için bkz. [src/service/README.md](src/service/README.md)) |

Klasörler build sırasına göre listelendi — her katman, kendinden öncekinin
üzerine aktive ediliyor (`dictionary`, `behavior`'dan önce geliyor çünkü
behavior implementation class'ı number range object'i çağırıyor).

## Kurulum / Aktivasyon

1. Bağımlılık sırasına göre aktive et: `database` → `data-model` →
   `dictionary` → `behavior` → `projection` → `metadata` → `service`.
2. `ZI_PR_HEADER_AD.bdef`'i aktive ederken, ADT draft tablolarını
   (`zpr_header_ad_d`, `zpr_item_ad_d`) eksik olarak işaretlerse, bunları
   üretmek için doğrudan `draft table` satırlarında sunulan Quick Fix'i
   kullan — bunlar bu repoda elle yazılmış kaynak dosyalar değil, ADT
   tarafından aktivasyon sırasında üretiliyor.
3. Bu proje kurulurken birkaç sıra dışı, sisteme özgü aktivasyon sorunuyla
   karşılaşıldı (`TYPE TABLE FOR UPDATE`'i bloke eden bir RAP/EML tip
   üretimi hatası, release edilmemiş bir kontrol tablosuna ihtiyaç duyan
   `CURR`/`QUAN` alanları, döngüsel root/child CDS aktivasyon sırası ve
   daha fazlası) — hepsi kök sebep ve çözümüyle birlikte
   [docs/type-table-for-update-workaround.md](docs/type-table-for-update-workaround.md)
   dosyasında belgelendi. Yeni bir sistemde aktive etmeden önce okumakta
   fayda var; çözümler bu repodaki koda zaten işlendi ama *neden*
   böyle yapıldığı sadece koddan anlaşılmıyor.
4. Service binding oluşturma ve Fiori Elements uygulamasını önizleme dahil
   eksiksiz adım adım talimatlar
   [docs/cds-odata-setup-guide.md](docs/cds-odata-setup-guide.md)
   dosyasında.
